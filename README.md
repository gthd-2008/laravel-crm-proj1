## What I learned initially:
- OOP (improved my understanding of it)
- what are namespaces
- what is a 'scope'
- what an ORM is (improved my understanding of it)
- one-to-one, one-to-many and many-to-many relationships
- what an MVC is

## What are the flaws:
- too ambitious of a project for a person who barely knows programming and is not acquainted with Software Development standards.
- monolithic codebase, no front-end and back-end separation
- no tests, no meaningful logging, no metrics -> painful debugging
- mostly vibe-coded codebase
- non-deterministic commits, like "feature {featureName} should work now"

What could have been done differently:
- the idea could be simpler
- phase 1 of the project could have been an architecture design instead of "just go with the vibe"
- a more lightweight framework or the Vanilla php could have been used
- tests would help a lot
- metrics, logs and traces could have been added for better debugging
- Docker could have been used to containerize the application
- AI could be used as a search engine instead of as the project generator

## Verdict?
Vibe-coded codebase. Not production ready. There is code in my bugs.
Use for the real world? None. Use for me? I have learned a lot from my mistakes. Will not make them again in my new projects (although I made a few of them in some of the other old projects).
